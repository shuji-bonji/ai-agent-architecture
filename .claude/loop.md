# 翻訳品質ゲートの自走ループ

`.claude/translation.json` の設定に従って、英日ページ対の翻訳品質を保つ。設定を読んでから始める。

## 各イテレーションでやること

1. 前回のイテレーション以降に変更された Markdown を拾う。作業ツリーの変更は `git status --short`、コミット済みの変更は `git diff --name-only HEAD~1 HEAD` で見る。
2. 変更されたファイルからページ対を特定する。`localeRoots` の対応（`docs/ja/X` ↔ `docs/X`）と `filePairs` の明示ペアを使う。`exclude` の glob に一致するものは対象から外す。
3. 対ごとに原文の言語を決める。既定は `defaultSource`。`sourceOverrides` の glob に一致する対は、そちらの `source` が優先する。
4. `/check-translation <対のパス>` を実行する。原文を `source_lang`、訳文を `target_lang` として xCOMET で採点する。
5. `threshold` を下回るセグメントがあれば、原文を正として訳文側だけを直す。
6. 直したら 4 に戻って採点し直す。

## 停止条件

- 対象の全セグメントが `threshold` 以上になったら、直したページ名とスコアを 1 行ずつ報告して停止する。
- 同じページで `maxFixRounds` 回直しても閾値に届かない場合は、ページ名・スコア・該当セグメントの原文と訳文を出して停止する。機械的に直せない訳は人が決める。
- 変更されたページが 1 つも無ければ「変更なし」とだけ言って停止する。

## やらないこと

- 原文の書き換え。このループが直すのは訳文だけである。
- 対の片方だけを追加・削除すること。英日は対称に保つ。
- コミットと push。差分は作業ツリーに残し、人が確認する。
- `threshold` や `sourceOverrides` の変更。設定を緩めて合格させるのは、ゲートを外すことと同じである。閾値に届かないなら、そう報告して止まる。
